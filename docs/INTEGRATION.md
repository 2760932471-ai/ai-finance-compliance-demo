# 原系统合并说明 v0.5

## 合并结论

有必要合并功能，但不能将两个同名 `app/`、`server.py` 直接覆盖。采用原 v0.4 为主体，将独立扩展迁移为 `compliance/`，保留原四入口。

## 已实现

- 同一服务：原 `/api/*` 保留；新增 `/api/compliance/*`，统一经过原 Host/Origin/会话令牌校验。
- 同一数据库：默认 `data/audit.sqlite3`。原审核保留 `objects` 表；合规配置、运行、研判和审计用独立表，事务保存。
- 同一页面：审核中心接入模型与本体；运营中心接入风险研判、关联图谱、配置审计和工具。新视图在Shadow DOM内隔离样式，不运行第二个服务器。
- 事实桥接：原审核工作台填写经人工确认的业务字段、选择证据页；校验引用存在性，保存原运行编号、证据编号、证据摘要、原包摘要、确认人和依据。
- 风险运行快照保留事实和引用；支持跳回原件页。原单据审核与跨业务风险研判分别记录，不互相覆盖结论。
- 导入的原件引用也经过存在性和摘要检查，不能导入伪造引用。
- 不兼容本体发布被阻止；业务导入/模型发布不改写已保存运行。
