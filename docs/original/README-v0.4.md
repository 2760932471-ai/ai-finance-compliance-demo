# AI财务审核 · 财务费用 AI 审核

按比赛 T1 活动类（经销商垫付 F 类）建设的本地单用户应用。以原始 ZIP 为入口，完成材料治理、原件识别、65 项审核、证据对照、人工复核、AI 问答和离线 PDF / HTML 报告。无需 Dify。

当前应用版本 **v0.4**（2026-10-14）：默认PDF导出、三格式不可变快照、可解释人工复核、本机来源/路径/请求防护。开发前规格见 [SDD-04](docs/SDD-04-REPORT-SECURITY.md)，实现与验证见 [实施记录](docs/SDD-04-IMPLEMENTATION.md)。

## 启动

**本机2026-10-12更新：StartLux CPU服务已安装，shadow对比模式、仅复核P0重点规则。当前网页地址为 http://127.0.0.1:18765/ （原8765被其他服务占用）。详细运行证据见 [StartLux本机接入记录](docs/StartLux本机接入记录.md)。**

约定环境：Windows 10/11、Python 3.11+、中文 Windows OCR 语言包、已安装并登录的 Codex CLI。此电脑可自动使用 Codex 附带的 Python。

1. 双击 `启动系统.cmd`；或在项目目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File start.ps1`。
2. 此电脑打开 <http://127.0.0.1:18765/>。其他电脑按启动脚本显示的地址访问，未配置 PORT 时默认 8765。已运行时脚本会复用服务。
3. 停止服务：双击 `停止系统.cmd`。数据保存在 `data/`，重启后仍可查看。

其他电脑首次使用，先安装依赖并登录 Codex：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
codex login
powershell -NoProfile -ExecutionPolicy Bypass -File start.ps1
```

也可直接运行 `python server.py`。初始 OCR 使用系统 Windows PowerShell 5.1 的 WinRT 接口，随后默认对照原图进行视觉转写。原始 OCR 与转写分别保存；识别失败或看不清会明确提示，不将失败视为材料缺失。

## 怎么使用

- **开始审核**：填写项目，上传原始 ZIP。系统保留原包、恢复中文路径、过滤系统文件、去重并识别 PDF、扫描件、照片和离线 HTML。
- **审核工作台**：左侧原件，右侧问题；点击证据编号跳转页。可筛选全部 65 条、查看识别文字、校正文字、补证复审、询问审核助手。
- **人工复核**：逐条填写依据与复核人，保留 AI 原判。确认版本不会把不通过或待判断改成通过。校正与补证新建运行，旧报告不改写。
- **项目管理**：查看运行历史、归档和恢复项目。
- **审核中心**：65 条比赛原文规则锁定；知识可录入或导入 TXT/Markdown，保存草稿、发布和停用。仅已发布知识进入后续审核，每次留版本快照。
- **运营中心**：实际项目统计、规则风险、反馈候选；经核实的具体条目可填写预期结论并建立回归样本，再对比相同材料的最新系统原始输出。
- **报告**：默认生成可搜索、带分级书签和页码的A4 PDF，同时保存比赛要求的自包含HTML和JSON快照。包含65条完整结果、证据图、AI原判/人工意见、识别不确定性和执行来源；长证据文字在PDF中明确标注摘录，全文保留在HTML/JSON。历史报告按生成时固化，后续改判不会覆盖；下载时核验SHA-256。

## AI 审核是怎样执行的

主模型复用本机已登录的 Codex。应用调用官方 `codex exec`，禁用工具操作，以只读、临时会话和结构化输出约束分析提供的原件与规则。65 条规则合并审核，避免五次重复传递图片；输出缺失或无效时，仅补跑未通过校验的条目，最多一次。

原件保存和初始 Windows OCR 在本机完成；视觉转写与主审核需要在线模型调用。**模型推理会把当前审核材料传给当前 Codex 登录所使用的模型服务，并消耗账户用量**。本地网页不等于离线大模型。应用不读取、记录或复制登录凭据。额度、网络或模型失败会标为技术未完成，不伪造通过结论。

Harness 已实现：原包与输入指纹、规则及知识快照、结构化结果检查、65 项覆盖检查、证据引用检查、确定性金额核对、定向重试、运行日志、相同输入缓存、人工改判留痕和回归评测。结构校验不是业务准确率证明。

模型缓存键包含完整提示、输出约束与实际附图内容。规则、知识、识别内容或图片变化会重新调用。界面“执行校验”显示缓存来源，不能把缓存命中计作新模型推理。

## 图片识别与独立决策复核

图片与扫描页默认使用原图和底部水印裁切进行视觉转写，明确标记不清区域，不以语境补猜字。保留原始 Windows OCR、模型版本及调用记录。用户截图中的 D031-P1 已恢复日期时间等可读水印；被遮挡的招牌仍标为不确定。这不意味着所有图片或关键字段100%准确。

首次完整审核会额外进行视觉转写调用，两份现有考试包的31页分4批；实测这些批次合计约792秒，之后65项主审核另需约439秒，不能把缓存重跑约30秒当成新推理速度。图片内容与提示相同才复用缓存。可设置 `AUDIT_VISUAL_OCR=off` 停用转写，原始 OCR 将作为未经确认候选保存，不伪装成可靠文本。

新增可切换 `off / jev / startlux` 决策层。两个 Choice 分别判断事实支持度和规则结论；Jev只发送文字，StartLux可显式附原图。源码模板默认关闭；本机已启用StartLux CPU文本版并进行真实联调，Jev仍未启用。配置凭据/端点后先用 `shadow` 记录对比，`gate` 才将冲突或不确定的通过项转人工，永不自动放行。两种模式均保存概率与调用来源，阈值0.8未作业务标定。

架构、独立部署要求与配置示例见 [架构与决策模型接入](docs/架构与决策模型接入.md)。当前电脑已安装StartLux轻量权重；源码包不附模型文件，其他电脑需独立安装。

## 配置

新电脑首次使用可复制 `.env.example` 为 `.env`；此电脑已有配置，请勿覆盖，只修改需要的项：

| 变量 | 用途 |
|---|---|
| `AUDIT_AI` | 默认 `codex`；`off` 关闭模型，仅整理识别，语义项保持技术未完成 |
| `AUDIT_CODEX_PATH` | 可选，指定 Codex 可执行文件；为空自动查找 |
| `MODEL_TIMEOUT` | 单次模型调用超时秒数，默认 600 |
| `AUDIT_CACHE` | 默认 1，复用完全相同输入；0 关闭 |
| `PORT` | 本机端口，默认 8765 |
| `AUDIT_PDF_FONT` | 可选中文TrueType字体路径；Windows默认使用系统微软雅黑，不在源码包分发字体 |
| `AUDIT_VISUAL_OCR` | 默认 on，原图视觉转写；保存原始 OCR |
| `AUDIT_DECISION_PROVIDER` | 默认 off；可选 jev 或 startlux |
| `AUDIT_DECISION_MODE` | 默认 shadow（只记录）；gate 可将通过转人工 |
| `DECISION_CONFIDENCE` | 默认0.8，须用业务金标标定 |
| `STARTLUX_ENDPOINT` / `STARTLUX_MODEL` | 独立部署的SystemOne服务及实际模型名 |
| `STARTLUX_IMAGES` | 默认off；PyTorch视觉服务才可on |
| `STARTLUX_AUTOSTART` | on 随主应用启动已安装的本机 StartLux 服务 |
| `STARTLUX_REVISION` | 部署清单哈希；变更版本后使缓存失效 |
| `DECISION_TIMEOUT` / `DECISION_SCOPE` | 请求超时秒数 / all 或 p0；本机180秒、p0 |
| `STARTLUX_API_KEY` | 可选，自己的远程认证代理密钥 |
| `AUDIT_JEV` | 兼容旧配置；显式provider优先 |
| `TYPESAFE_API_KEY` | Jev 服务密钥，仅保留后端环境 |
| `JEV_MODEL` | 默认固定 `jev-1.13.0`，避免别名漂移 |
| `JEV_CONFIDENCE` | 转人工阈值，默认 0.8 |

密钥和运行材料不进入源码交付包。`data/` 含业务原件、识别文字和报告，请按业务资料管理；备份时保留整个目录。

## 本机安全与报告运行

仅监听127.0.0.1；请求必须来自指定Host/端口及同源页面，跨站请求拒绝，写操作需要临时会话令牌。限制上传/JSON大小及待处理任务数量，拒绝非预期传输和越界文件路径；错误响应脱敏。安全事件只留时间、资源、状态等元数据，不记录请求正文或密钥。令牌不等于企业身份认证，文件摘要不是数字签名。

PDF依赖ReportLab 4.x和中文字体。若字体缺失，请配置 `AUDIT_PDF_FONT` 后重新导出；失败不会登记成功报告。历史HTML继续可以下载。诊断参考 `data/server-error.log`，业务材料、完整快照和模型记录应按内部敏感资料管理。依赖来自Python标准库、pypdf、pypdfium2、Pillow、ReportLab；StartLux来源及固定部署版本见接入记录，字体使用系统已有文件。

## 边界

这是本地演示与单用户验证版，尚无多人权限体系、生产任务队列、财务系统对接或发票外部查验。印章真伪、扫码真实性、预算有效性等缺外部依据时保留待判断。知识导入当前支持 TXT/Markdown；业务审核材料支持 PDF、图片、HTML。图片证据定位到文件与页，尚未生成问题区域的准确框选。

每个项目保留所有运行；运营风险按项目最新运行统计，不把多个规则命中视作独立违规事件。两套考试素材的业务内容哈希相同，能验证包装治理和复现，不能证明对多个独立业务场景的准确率。

评分依据和缺口见 [评分对照与差距](docs/评分对照与差距.md)，不承诺90分。
